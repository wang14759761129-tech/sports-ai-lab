# PTTI Vision Benchmark v0

Research-only foundation. Product branch baseline: `1052321db6887af5db4417aeaabb46124e9ad8f6`.
No model replacement, Hit parameter tuning, desktop migration, production DB access or release.

## Contract

`VisionModelAdapter -> FrameObservation(timestamp_ms, source_frame, detections) -> evaluate_ball -> JSON/HTML`.
Core imports only Python standard library. Model inference, decoding and runtime profiling belong in isolated workers.
Keep model name/version/checkpoint hash, exact score semantics, code revision and code/weights licenses in every run.
Scores are model outputs, not calibrated probabilities. Keep multiple detector candidates: additional false targets must count.
No model can modify manifest or annotation assets. Verify SHA256 before a run. Reports refuse overwrite.

## Metrics

Presence recall: any ball detection on a visible GT frame. Localization recall: nearest detection within 20 source pixels.
Report both, center mean/median/P95, normalized error and >20/50/100px buckets. Wrongly localized detections and extra candidates count as FP.
Unlabeled frames are not negatives. Sparse labels cannot yield credible full-video FP/min, FN/min or true trajectory accuracy.
Full prediction streams can measure prediction fragment count, average fragment length, longest continuous/missing run and recovery;
those are continuity, not accuracy. When stream is sparse, metrics explicitly say `SPARSE_NOT_EVALUABLE`.
Scene-stratum comparisons need reviewed labels and enough samples; otherwise `NOT_AVAILABLE`.
Record FPS, cold startup, process RAM, CUDA allocated/reserved VRAM, install footprint and stability independently.

## Downstream Hit experiment

## CVAT workflow

1. Run official CVAT Community Docker deployment only in a suitable separate annotation environment. CVAT is never a desktop dependency.
2. Create one project with `cvat-labels.json`; start with BALL points/boxes and HIT tags, plus explicit BALL_ABSENT tags.
3. Import representative short clips or the image tasks. Preserve `cvat_frame_map.json` and source video SHA.
4. Annotate then review, retaining reviewer identity, uncertain frames and timestamps. Never equate absent shape with absent ball.
5. Export native CVAT 1.1 XML. `ptti_benchmark.cvat.read_cvat_xml` maps explicit source frames/timestamps and retains native fields/attributes.
6. Tracking outside=1 is UNKNOWN, not a negative. Only explicit annotations are imported; interpolated track shapes are not generated by the adapter.
7. Benchmark promotion requires reviewed annotations and hashes; first measure a real 100-event annotation task before claiming time saved.

Current machine has no usable Docker command or Docker Desktop executable. No CVAT service/UI session was run;
adapter synthetic engineering QA is not CVAT human-workflow acceptance. A deployment-ready queue is prepared locally.
