## Cover-source review

The isolated QA feed contained nine catalog records: eight YouTube records attributed to the World Table Tennis channel and one Bilibili record. This review did not change source records or upgrade playback/completeness states. The feed now renders an official remote thumbnail only when an explicit `ALLOWED` display-permission value is present in a recognized source field and the image URL uses HTTPS. Otherwise it uses the PTTI fallback cover. This is a conservative product rule, not a legal determination about any individual image.

The YouTube image URLs below use the stored `hqdefault.jpg` pattern. The catalog contains no explicit thumbnail-display permission for any of them. Actual image files were not fetched, so their per-file dimensions and sharpness were not measured. YouTube's thumbnail reference describes a nominal 480×360 `high` image and notes that returned sizes can vary; this is not proof of the dimensions of these individual files: [YouTube thumbnail resource](https://developers.google.com/youtube/v3/docs/thumbnails). The 16:9 card uses `object-fit: contain`, so an approved image will not be stretched or cropped; the existing container provides a consistent ratio.

## Visual and interaction review

The real local feed preview was rendered with a temporary isolated QA database and the feed-preview flag enabled. Screenshots are browser-rendered product-source evidence, not Windows-native acceptance and not evidence that any external video played during this sprint.

| Viewport | Observed layout | Evidence |
|---|---|---|
| 1440×1000 | Four-column feed, compact horizontal navigation, 16:9 cards | `reports/premium-design-v1-1/video-feed-1440.png` |
| 768×1024 | Two-column feed without horizontal overflow observed | `reports/premium-design-v1-1/video-feed-768.png` |
| 390×844 | Single-column feed with stacked compact header | `reports/premium-design-v1-1/video-feed-390.png` |

The 390px capture was taken just before the final CSS-only adjustment. Visual inspection suggested the search input's intrinsic minimum width could crowd the header at narrow sizes; `studio-shell.css` now sets `min-width: 0` on that input below 640px. The screenshot remains evidence of the one-column layout, but the final input sizing change was not re-captured in a browser during this pass; narrow-header post-change visual confirmation remains `NOT_TESTED`.

Cover loading uses native lazy loading and asynchronous image decoding. Repeated thumbnail text is marked decorative for assistive technology because the title is rendered next to it. The PTTI placeholder stays inside the 16:9 frame, uses a short, ellipsized status label, and remains visible after an image load error. Approved remote covers use `contain` to prevent crop; hover changes brightness without scaling or clipping the image.

The source UI and existing logic checks cover loading/empty/error, no-embed, restricted and external-watch states. A separate screenshot of loading/error states was not captured in this pass. Contrast, keyboard-focus and reduced-motion styles were inspected in the existing design system; no dedicated assistive-technology audit or measured CPU/memory benchmark was run. Performance measurements are therefore `NOT_MEASURED`.

## Changes in V1.1

- `frontend/src/feedCatalog.ts`: gate official thumbnails on explicit permission plus HTTPS; attach contextual fallback labels.
- `frontend/src/VideoFeed.tsx`: reset image error state when the source changes; use lazy loading, async decoding, and decorative image semantics.
- `frontend/src/video-feed.css`: use non-cropping cover fit and a compact, bounded fallback label; consolidate the fallback style rule.
- `frontend/src/studio-shell.css`: allow the mobile search input to shrink within its grid cell.
- `frontend/scripts/test-video-feed.mjs`: cover missing permission, explicit root and canonical-source permission, and insecure HTTP cases.

No source catalog rows, rights values, external URLs, player protocol, desktop launcher, activation pointer, or database were modified.

## Integration handoff

This branch changes only the feed catalog presentation, feed card and shell CSS, its feed contract test, screenshots, and this QA report. It does not touch the Vision player, playback recovery, external-link bridge, or WebDex's separate `products/ptti-web` application. The next integrator can cherry-pick this branch's V1.1 commit onto the chosen shared base after reviewing `feedCatalog.ts`, `VideoFeed.tsx`, `video-feed.css`, `studio-shell.css`, and the added feed tests.
