## Visual and interaction review

The initial V1.1 feed preview used an isolated QA database and feed-preview flag. The final closeout screenshots below use the current React feed and shell components with a temporary visual-only fixture based on the reviewed source IDs. Fixture titles are explicitly labeled as layout samples; no match title, competition, player, playback, or completeness fact is asserted by those screenshots. They are browser-rendered source evidence, not Windows-native acceptance and not evidence that an external video played.

`video-feed-desktop-final.png` is retained as a supplementary earlier desktop capture using a shorter QA-only title fixture; the three `*-final.png` viewport files above are the canonical final breakpoint evidence.

The final screenshots were captured with Microsoft Edge in an isolated headless browser using exact CSS viewports at device scale factor 1. Measurements were: 390×844 — search field 220px wide with 14px right inset, one column; 768×1024 — search field 190px wide, two columns; 1440×1000 — search field 260px wide, four columns. At all three sizes, document `scrollWidth` equalled `clientWidth` (390, 768, and 1440px), and the card cover ratio was 1.778. The long Chinese layout-only title stayed within its two-line clamp. Seven Tab presses reached the search input with `:focus-visible=true` and a red focus border. These are browser QA observations, not native Windows checks.

Cover loading uses native lazy loading and asynchronous image decoding. Repeated thumbnail text is marked decorative for assistive technology because the title is rendered next to it. When a cover is unavailable or not display-authorized, the new PTTI-owned CSS/SVG fallback stays within the 16:9 frame and shows a stylized paddle, ball, and motion arcs with an explicit “非比赛画面” label. It uses only the catalog's existing event/category/participant text, with “待核实” text when data is absent; it does not use or imitate a match photograph. Approved remote covers use `contain` to prevent crop; hover changes brightness without scaling or clipping the image.

The source UI and existing logic checks cover loading/empty/error, no-embed, restricted and external-watch states. A separate screenshot of loading/error states was not captured in this pass. Contrast, keyboard-focus and reduced-motion styles were inspected in the existing design system; no dedicated assistive-technology audit or measured CPU/memory benchmark was run. Performance measurements are therefore `NOT_MEASURED`.

## Changes in V1.1

- `frontend/src/feedCatalog.ts`: gate official thumbnails on explicit permission plus HTTPS; attach contextual fallback labels.
- `frontend/src/VideoFeed.tsx`: reset image error state when the source changes; use lazy loading, async decoding, and decorative image semantics.
- `frontend/src/video-feed.css`: use non-cropping cover fit and a PTTI-owned CSS/SVG placeholder with bounded metadata; consolidate the fallback style rule.
- `frontend/src/studio-shell.css`: allow the mobile search input to shrink within its grid cell.
- `frontend/scripts/test-video-feed.mjs`: cover fallback metadata, missing permission, explicit root and canonical-source permission, and insecure HTTP cases.
- `frontend/scripts/test-dark-studio.mjs`: assert responsive column breakpoints, 16:9 framing, search sizing, and keyboard focus styles.

No source catalog rows, rights values, external URLs, player protocol, desktop launcher, activation pointer, or database were modified.
