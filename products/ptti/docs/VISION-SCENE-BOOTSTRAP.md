# Vision Lab v2: Real Scene Bootstrap

This is a research-only keyframe detector for the staged Extended OpenTTGames training video `game_4.mp4`. It runs outside the desktop and BallTrack Python environments, then stores reviewable detections and frame images under `%LOCALAPPDATA%\PTTI-Dev\vision-v2\scene-bootstrap`. The desktop reads this Dev-only folder; it does not read or write the Production database.

The source is from [moamal01/table_tennis_data](https://github.com/moamal01/table_tennis_data), pinned locally to revision `36471a76b969a0340df59258a813bf8214e68e7c`, under CC BY-NC-SA 4.0. The staged `game_4.mp4` is 1920×1080, 120 fps CFR, 526 seconds, 63,120 frames; SHA-256 `DDB2BC49915A99DB46702825FF322759FAA9205C846A1BA902419E38C1E23B39`. This material and all derived visual evidence are non-commercial research material and are excluded from product installers, releases, and Git.

The isolated runtime uses `IDEA-Research/grounding-dino-base`, pinned to `a062f8edaf7f3aa52714a8f80cb8db7de1e5e170`. Its `model.safetensors` checkpoint is accepted only at 933,400,872 bytes with SHA-256 `5548f844c928c4b6f411fa8cbcc2bfa8dbbba437cb1d513975519f93c2a9ed21`; model code and checkpoint are Apache-2.0. The runtime reuses the installed BallTrack PyTorch package read-only and installs other packages only in `%LOCALAPPDATA%\PTTI-Dev\vision-v2\venv`.

The selected prompt is `table tennis table. person. referee. scoreboard.` with 0.25 detector and text thresholds. A small prompt comparison used the same 28 sampled frames: this prompt produced left-and-right player-side candidates on 67.9% of frames; `table tennis table. table tennis player. referee. table tennis scoreboard.` did so on 39.3% and sometimes merged people into a mixed label. These are detector coverage counts, not accuracy measurements. Player A/B identity is never inferred from screen side. Spatially central people remain referee/other candidates. `detector_score` is an uncalibrated model output.

The video is sampled every 20 seconds and after histogram scene-change candidates. No scene changes were detected in this static-camera sample, so only periodic samples were used. The lightweight detector remains connected to the keyframe sampler for future cut-triggered re-detection. The sample did not produce a reliable scoreboard box; OCR remains disabled. In the desktop's Video Analysis → Scene Candidates view, users can compare original and overlay frames, click a box, assign a human role, or reject it. Corrections append to `reviews.json`; `scene_bootstrap.json` remains the immutable raw result.

The current coverage indicates the table was found in all 28 sampled frames, and both court-side person candidates were present in 67.9%. This is a single fixed-view research video without object-level ground truth. It does not certify person identity, table-box tightness, cross-match generalization, or scoreboard detection. Do not treat this as commercial product readiness or as evidence to enable SAM 2 until a more representative real-video sample passes review.
