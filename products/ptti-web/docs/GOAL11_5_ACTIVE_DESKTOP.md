# One desktop entry, local accepted-release registry

Stable location: `%USERPROFILE%\PTTI\Web-Pro`. `Start-PTTI-Active.ps1` reads `active-release.json`, then an immutable `releases/<id>.json`. No downloads, scheduled updater, installation or in-session update. The initially accepted release is the existing4174 local review preview, based on the user's confirmed GOAL11.1 acceptance. Its runtime still requires the existing development worktrees; source files/Core/launcher/config are hash-pinned. A different Git HEAD caused only by installer/docs changes is reported, not treated as a different browser build. Source changes affecting pinned files fail closed until a new reviewed record is registered. This is deliberate: latest committed code is not automatically latest accepted product.

`Set-PTTI-Release.ps1 -Register <release.json>` accepts only `ptti.local-release/0.1`, status ACCEPTED, startup/core_flow/privacy gates true, matching file and evidence hashes. It never overwrites a registered ID. These are local operator acceptance records, not signatures or an automatic proof of test truth. Each future immutable candidate needs real startup, core browser and privacy evidence; blocked4177 does not qualify. Include its launcher and manifest resources in files, expected health identity and actual package SHA/evidence. Review the candidate before registering it. No arbitrary remote update feed is read.

`Set-PTTI-Release.ps1 -Activate <registered-id>` backs up and atomically replaces only the active manifest under a shared mutex. Previous current becomes fallback. Running sessions are untouched; the next desktop launch reads the new choice. On integrity/startup/health failure, the launcher tries only registered accepted fallbacks and logs the reason. A fallback applies for that launch only; active selection is not silently rewritten. Operator rollback uses `-Activate <previous-id>`. No release/fallback is downloaded or installed, and no old process is stopped. Delegated launchers retain bounded startup and service-specific mutex/identity checks. Browser RAM failure does not trigger a version downgrade.

The desktop shortcut remains named PTTI Cinema with its original icon. Duplicate shortcuts are moved, not deleted; native executables, data and4174/4176/4177 remain. Backup inventory records actual targets/arguments/icon/SHA; the original desktop link and fixed launcher are retained for byte-for-byte recovery. Independent Shell activation with -NoBrowser verifies registry/service reuse without launching another browser. Default-browser open and physical user double-click must be reported separately, especially under RAM constraints.
